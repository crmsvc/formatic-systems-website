A tool gets switched on when a business owner can tell at a glance what it does. Use plain names, keep look-ups apart from changes, give each tool one job, and say up front if it sends a message, moves money or deletes something.

## Names and descriptions a business owner can read

The person approving your tool runs a plumbing or cleaning business. "Look up a customer by phone number" gets switched on. "execute_query" does not.

## Reading kept apart from writing

One tool that looks something up, another that changes it. A tool that does both has to be treated as a write, so the owner can't give it the lighter setting.

## One job per tool

A tool that does a single clear thing is easy to judge. A tool with a mode switch that can do ten things is not.

## OAuth sign-in

Owners are used to "sign in and allow". It also means access can be taken away from your side without anyone copying keys around.

## Say plainly what leaves the building

If a tool sends a message to a customer, moves money, or deletes or cancels something, say so in the first sentence of its description. Those uses always wait for the owner's approval, and a clear description is what gets them approved.

## Keep descriptions steady

If a tool's description changes after the owner has reviewed it, the tool switches itself off until the owner reviews it again. Change descriptions when the behaviour changes, not for wording.

## Return only what was asked for

Send back the fields the task needs. Smaller answers are faster on a live phone call and put less of a customer's data in play.
